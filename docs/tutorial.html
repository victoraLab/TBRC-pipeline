TBRC tutorial

From a FASTQ pair to annotated wells

This page takes you from a fresh download to your first finished run. Allow up to 30 minutes the first time. Most of that is a one-time build of the software; a small run takes about a minute.

  1. ReadsThe FASTQ files of one library
  2. Trim and mergeAdapters off, read pairs joined
  3. Sort into wellsBarcodes give plate, row and column
  4. Pick sequencesThe top sequences of each well
  5. AnnotateV, D and J genes with IgBLAST, clones if you ask
  6. DeliverA report, tables and an archive

A

Choose a route

Pick the one closest to what you want. The rest of this page then shows only the steps for that route. You can change your mind later by running the setup again.

Not sure? Start with This computer, terminal. It is the quickest way to see TBRC work.

Tested on one Apple Silicon Mac; not tested on Linux or Intel. The software may not build or may behave differently there.

Run the setup

Download TBRC and start the guided setup. It asks one question at a time, and asks again if an answer is not valid. Type the number of your choice.

git clone https://github.com/victoraLab/TBRC-pipeline.git TBRC
cd TBRC
./tbrc setup

Before you open the web app to the whole lab. The app listens on your network over plain HTTP, so the password and everything uploaded cross the network unencrypted. Everyone shares one password and there are no user names, so anyone who logs in can submit a run under any user id. To add HTTPS, follow the comment at the top of deploy/docker/Caddyfile.

What is left to do on the cluster

When it finishes, the setup prints these four steps with your own paths filled in. Do them once, then run ./tbrc check.

  1. Copy backend/ and environment.yml to the cluster with rsync.
  2. On the cluster, create the conda environment.
  3. On the cluster, build the IgBLAST databases. This needs NCBI's internal_data/ and optional_file/ folders; see backend/igblast_setup.md.
  4. Make sure ssh reaches the login and data-transfer hosts with a key and no password prompt.

During the IgBLAST step you will see many lines saying Skipping duplicate seq_id. That is expected: some T-cell genes are listed under both TRA and TRD, and each is kept once.

D

Check it works

The setup already ran this check. Run it again at any time.

./tbrc check --local
./tbrc test

The check should end like this. The first lines list placeholder cluster names, which runs on your computer do not use.

== this machine (for --local runs)
[ OK ] pipeline tools: not on PATH, but Docker image tbrc-backend:arm64 is available
[ OK ] IgBLAST internal_data in backend/igblast
[ OK ] IgBLAST mouse ig_all panel built locally
[ OK ] IgBLAST human ig_all panel built locally

All checks passed.
./tbrc check
./tbrc test

Every [FAIL] comes with a line starting -> that says what to do. ./tbrc test needs no data: it confirms that the workflow can plan a run.

E

Make a small library

Take the first 100,000 read pairs of one of your libraries. A read is four lines in a FASTQ file, so that is 400,000 lines. Keep R1 and R2 in the file names, and put nothing else in the folder.

mkdir mini
gzip -dc /path/to/sample_R1_001.fastq.gz | head -n 400000 | gzip > mini/mini_R1_001.fastq.gz
gzip -dc /path/to/sample_R2_001.fastq.gz | head -n 400000 | gzip > mini/mini_R2_001.fastq.gz

Names may use letters, digits, ., _ and -, with no spaces. TBRC refuses anything else and tells you which field to fix.

F

Run it

Terminal route 
./tbrc run --local --cores 8 --user me --run-name first_test --fastq-dir mini \
    --primer-set T --pipeline tiago_vsearch --species mouse --panel trb --clonality

This example is for mouse T cells. For B cells use --primer-set B2 and --panel ig_all. A library of this size took 41 seconds on 8 CPUs of an Apple Silicon Mac.

Cluster route 
./tbrc run --user me --run-name first_test --fastq-dir mini \
    --primer-set T --pipeline tiago_vsearch --species mouse --panel trb --clonality

The files are copied to the cluster and the terminal follows the run. Expect tens of minutes, so use tmux or nohup if you may disconnect. For data already on your file server, replace --run-name first_test --fastq-dir mini with --server labnas --folder plate_001, using the short name you gave in the setup.

OptionMeaning
--local --cores 8Run on this computer with 8 CPUs.
--user meWho the run belongs to. It names the results folder.
--run-name first_testThe name of this run. It starts every sequence name.
--fastq-dir miniA folder holding exactly one R1 and one R2 file.
--primer-set TThe barcode set of the library: B, B2, T, nanopore_IgG_IgK or your own.
--pipeline tiago_vsearchHow reads are assembled. tiago_vsearch is the default for Illumina. The others are classic_luka, tiago_sulkseq for MIBS libraries, and tiago_nanopore.
--species mousemouse or human.
--panel trbThe germline genes to annotate against: igh, ig_all, tra, trb, tcr_all, all_receptors or ig_b6. A check widens a single-locus panel when the plate needs it.
--clonalityAlso group sequences into clones.

Add --dry-run to see what would be done without running it. ./tbrc run --help lists every option.

A finished run ends with its outputs marked OK:

8 of 8 steps (100%) done

[ OK ] IMGT-ready FASTA: first_test.imgt.ready.fasta
[ OK ] archive: first_test.zip
[ OK ] report: first_test.report.html
[ OK ] annotation status: qc/annotation/status.tsv
[ OK ] IgBLAST table: igblast/first_test.igblast.tsv

Using your own barcode set

A barcode set is a folder with two text files, BC1.txt and BC2.txt, each with a name and a barcode sequence on every line. Copy the layout of backend/data/barcodes/T/. A new set has no default trim sequence, so give it with --trim-seq (10 to 64 capital IUPAC letters). In the web app, use the barcode upload card on the left of the page.

G

Read the results

Results are in backend/results/me/first_test/first_test/, using your own user and run names.

Results stay on the cluster under results/me/first_test/ unless you add --push, which sends the archive to your file server.

FileWhat it is
first_test.report.htmlOpen this first. Receptor type, repertoire, wells by locus, plate maps, per-plate yield, read depth and sequence lengths. There is a PDF copy beside it.
first_test.imgt.ready.fastaThe final sequences with the 5' handle trimmed, ready for IMGT/HighV-QUEST.
first_test.final.fastaThe same sequences before that trim.
igblast/first_test.igblast.tsvOne row per sequence: locus, productive, v_call, d_call, j_call, the junction and more.
clonality/first_test.clonality.tsvThe clone of each sequence. .clonality.summary.tsv counts the sequences in each clone.
qc/The evidence behind the report, by stage. qc/assembly/well_verdicts.tsv says what happened to each well, and qc/annotation/status.tsv says what was annotated and how.
first_test.zipThe archive to keep or share. ARCHIVE_CONTENTS.txt inside it lists what it holds.

Reading a sequence name

Every sequence name says where the sequence came from:

first_testrun
P01plate
Arow
01column
_1rank in well
-149reads

By default TBRC keeps up to three sequences per well, so _1 is the most abundant. --contigs changes that number.

H

When it goes wrong

You seeWhat it meansWhat to do
[FAIL] in a checkSomething is missing or unreachable.Do what the -> line below it says, then check again.
error: sample.json refusedA value is not allowed. Nothing has been created or sent yet.Fix the fields it names.
run folder already existsThat user and run name were used before.Pick another --run-name, or add --force to reuse the folder.
A rule failedOne step of the workflow stopped.Read backend/data/runs/<user>/<run>/backend.log. Each step's log is under backend/logs/.
The web app does not startPort 8080 may be in use.Change TBRC_PORT in deploy/docker/.env and start it again.
A host counts as unreachableIt asked for a password. TBRC uses SSH in batch mode.Add a key for that host in ~/.ssh/config.

./tbrc ends with exit status 0 on success, 1 for a failed check or test, and 2 for a usage or environment problem.
